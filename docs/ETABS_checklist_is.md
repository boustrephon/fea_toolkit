# Structural FEA Model Review Checklist

## A Workflow-Oriented Document for ETABS and General Structural Analysis

> This checklist follows the natural sequence of a structural FEA workflow: planning, pre-processing, analysis, post-processing, and design. The **Answers** column should be completed on a project-specific basis. The **Guidance Notes** column provides practical advice, code references, and online resources. 
>
> Jurisdiction: **Indian codes (IS)** — generated from `docs/ETABS_checklist_src.md`; do not edit this file directly.

## Phase 1 — Model Planning & Setup

*This phase establishes the foundation of the model. Errors here propagate through everything downstream.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 1.1 | Has the intended use of the model been documented (e.g., drift check, element design, seismic assessment, staged construction)? |  | Document the analysis objective in the calculation plan before modelling begins. The choice of model type and stiffness assumptions should flow from this objective. For drift checks, a separate model with appropriate modifiers may be required; for element design, a model with strength-level stiffness is appropriate. |
| 1.2 | Is the chosen model type appropriate (e.g., 2D vs. 3D, frame vs. shell, linear vs. nonlinear, static vs. dynamic)? |  | The model type must match the analysis objective. A 3D model is generally required for seismic analysis; 2D models may suffice for isolated frame checks. Nonlinear analysis is required for pushover or staged construction assessments. |
| 1.3 | Have the model units been correctly set? |  | ETABS defaults to a unit system based on the model template. Always verify the unit system is consistent with the project (e.g., kN·m, kN·mm) before inputting any data. Mixing units is a common source of error. Check the units displayed in the status bar and in **Define → Units**. |
| 1.4 | Have the global in-plane axes been defined in accordance with the architectural layouts? |  | Verify that the global X and Y axes align with the building's principal axes. Check **Define → Coordinate Systems** and the on-screen axis display. Misaligned axes can lead to incorrect load application and results interpretation. |
| 1.5 | Has the concrete frame design option been set? |  | In ETABS, go to **Design → Concrete Frame Design → Design Preferences** and select the appropriate design code (e.g., IS 456:2000 for Indian projects). Ensure the code year matches the project specification. The design code influences reinforcement detailing, minimum/maximum limits, and capacity checks. |
| 1.6 | Have different stiffness reductions been assumed for the elements? Are you building the model for drift and displacement checking (both at ULS and SLS states) or for design of structural elements? |  | Stiffness modifiers (cracked section properties) are used to account for concrete cracking. For **ULS** (strength design), typical modifiers are 0.70 for columns, 0.35 for beams, 0.70 (uncracked) or 0.35 (cracked) for walls, and 0.25 for flat slabs. For **SLS** (serviceability), a separate model with higher modifiers (e.g., 0.70 for beams and columns) may be used. Ensure the correct model is used for the intended check. The 0.70/0.35/0.25 cracked-section modifiers follow ACI 318-19 (Table 6.6.3.1.1(a)); IS 456 does not codify specific values, so adopt them explicitly in the design basis. |
| 1.7 | Has the mass source been correctly set (recommended “from loads” option with adequate load factors for seismic combination)? Have there been additional point/line/area masses been declared if the case? |  | The **Mass Source** should be set to “From Loads” with a load combination that represents the seismic mass (typically DL + 0.25 LL or as per code). ETABS offers three options: from self and specified mass, from loads, or from self and specified mass and loads. The seismic weight/mass calculated by ETABS should be verified against a manual calculation, and the two values should be near. Ensure that dead load is not double-counted and that additional masses for partitions, cladding, etc., are included if not already in the load patterns. Verify that mass is defined in all three translational directions (UX, UY, UZ). If UZ mass is zero, vertical earthquake effects are not being considered. |

## Phase 2 — Pre-Processing: Geometry & Materials

*This phase covers the physical definition of the structure.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 2.1 | Have the grid dimensions and storey heights been set correctly before drawing elements? |  | Set grid dimensions manually or via DXF import. Verify storey heights against the architectural floor-to-floor heights. Errors here propagate through mass, stiffness, and drift calculations. |
| 2.2 | Have the heights of the storeys been set in accordance with the architectural layouts? |  | Compare the storey heights in the ETABS **Story Data** table with the architectural floor-to-floor heights. Discrepancies here affect mass distribution, stiffness, and drift calculations. |
| 2.3 | Have the basic concrete properties been defined correctly? |  | Verify the concrete grade (f<sub>ck</sub>), elastic modulus (E<sub>c</sub>), Poisson’s ratio, and the reinforcement yield strength (f<sub>y</sub>) for both longitudinal and shear reinforcement. These values should match the design basis report and the concrete supplier’s data. ETABS calculates E<sub>c</sub> from f<sub>ck</sub> using the selected code; if a different value is required, it must be overridden manually. |
| 2.4 | Have material assigned to elements correctly? (e.g., same element size but different concrete grade found in same story) |  | Use the **Material List** table in ETABS to verify that each element is assigned the correct material. Pay particular attention to elements with the same section name but different concrete grades—these can easily be overlooked. A quick check is to select all elements of a given section and review the assigned material. |
| 2.5 | Have the elements of the structure been positioned in accordance with the architectural layouts? |  | Overlay the ETABS plan view on the architectural background (using **View → Set Background Image**) to check element positions. Pay attention to edge beams, columns, and shear walls. Check for unsupported walls or cantilevers, eccentric loads that might cause instability, and openings or recesses that affect slab continuity. |
| 2.6 | Have the dimensions, materials property type and property modifiers been set correctly in the frame section definition (for columns and beams)? |  | In the frame section definition, verify the section dimensions (b × h), material type, and any property modifiers (e.g., moment of inertia multipliers for cracked sections). ETABS allows modifiers to be applied per section; ensure these are consistent with the analysis assumptions. |
| 2.7 | Have the dimensions, materials property type and property modifiers been set correctly in the shell section definition (for slabs and walls)? |  | For shell sections, check the thickness, material, and stiffness modifiers (f11, f22, f12 for in-plane; m11, m22, m12 for out-of-plane). For walls, f11 or f22 control flexural stiffness depending on local axis orientation; f12 controls shear stiffness. Slabs typically require m11, m22, m12 for out-of-plane bending. |
| 2.8 | Have the column and beam elements been defined with the intended orientation of the local axes (hint: use extruded section option or local axes display)? |  | Display local axes (**View → Set Display Options → Frame Local Axes**) to verify orientation. For columns, the local-3 axis should be along the member length; for beams, local-2 and local-3 should match the intended bending directions. Incorrect orientation affects moment capacities and design results. |
| 2.9 | Have the slab and wall elements been defined with the intended orientation of the local axes (hint: use extruded section option or local axes display)? |  | Display local axes for shells (**View → Set Display Options → Shell Local Axes**). The local-1 and local-2 axes define the plane of the shell; local-3 is perpendicular. For walls, the local axes should align with the wall’s vertical and horizontal directions. |
| 2.10 | Have the material densities (unit weights) been defined correctly for all materials? |  | Verify the density/unit weight of each material (concrete, steel, masonry, finishes). Density feeds both the self-weight and the mass source, so an error here silently scales gravity reactions and seismic mass. Cross-check against IS 875 (Part 1): 1987 (unit weights of building materials) and the material supplier data. In ETABS, review **Define → Material Properties** and confirm whether mass density or weight density is used, keeping units consistent. |
| 2.11 | Have the structural steel and reinforcement material properties been defined correctly (grade, f<sub>y</sub>, f<sub>u</sub>, E<sub>s</sub>)? |  | For structural steel members, verify the grade and properties (yield strength f<sub>y</sub>, ultimate strength f<sub>u</sub>, modulus of elasticity E<sub>s</sub> = 2 × 10<sup>5</sup> N/mm<sup>2</sup>) against IS 800:2007. For reinforcement, verify f<sub>y</sub> and f<sub>u</sub> against IS 1786:2008 (e.g., Fe 500, Fe 550). In ETABS, check the steel material definition and confirm the design strength used for steel frame design. |

## Phase 3 — Pre-Processing: Elements & Connectivity

*This phase ensures the structural topology is sound before loads are applied.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 3.1 | Have the column and beam elements been assigned with their correct pre-dimensioned sections? |  | Use the **Frame Section List** table to review all assigned sections. Cross-check against the structural drawings or pre-dimensioning schedule. Common errors include using a column section for a beam or vice versa. |
| 3.2 | Have the slab and wall elements been assigned with their correct pre-dimensioned sections? |  | Check the **Area Section List** table and compare with the structural drawings. Ensure slab thicknesses and wall thicknesses match the design. |
| 3.3 | Have the frame elements been correctly connected to other points and elements (hint: use snap to points and grid option for the graphic construction of the model; split the elements to check the correctness of the connections)? |  | Use **Select → Select by Connectivity** or visually inspect joints to ensure elements are connected. Disconnected elements can cause instability or incorrect load transfer. ETABS may report “unconnected joint” warnings during analysis. Use ETABS “Check Model” tool (Analyze → Check Model) to identify unconnected joints. View the deformed shape under self-weight; excessively large or illogical deformations may indicate connectivity issues. |
| 3.4 | Have the shell elements been correctly connected to other points and elements (hint: use snap to points and grid option for the graphic construction of the model; split the elements to check the correctness of the connections)? |  | Use **Select → Select by Connectivity** or visually inspect joints. Shell elements must share nodes with adjacent frames or other shells for proper load transfer. |
| 3.5 | Have unconnected joints (“flying joints”) or orphan nodes been identified and resolved? |  | Use ETABS “Check Model” tool and review the analysis log for warnings. Orphan nodes or elements not correctly attached can cause numerical instability. Check the deformed shape under self-weight for anomalies. |
| 3.6 | Has the auto-merge tolerance been set appropriately? |  | An auto-merge tolerance that is too small can leave gaps between elements that should be connected. Conversely, too large a tolerance can merge joints that should remain separate. Check this setting against the model's smallest element dimensions. |
| 3.7 | Are frame releases required? If so, have they been set correctly (hint: use graphical option “frame releases”)? |  | In ETABS, go to **Assign → Frame → Releases/Partial Fixity** to check releases. Releases are typically required at the ends of simply supported beams or at the base of pinned columns. Avoid releasing moments at beam-column connections unless the connection is truly pinned—this can cause numerical instability. Multiple releases at a joint can orphan a degree of freedom, causing instability. |
| 3.8 | Have the end length frames offsets and rigid zone factors been correctly defined (e.g., generally use 0.5 value for the rigid zone factor and automatic offset from connectivity option)? |  | The rigid zone factor (RZF) represents the fraction of the end offset assumed rigid. A common value is 0.5 for beam-column joints. Using RZF = 0 ignores the stiffening effect of the joint; using RZF = 1 may over-stiffen the model. Check **Assign → Frame → End Length Offsets**. |
| 3.9 | Is the auto frame subdivide option required? If so, has it been activated? |  | Auto frame subdivide is used to ensure compatibility between frame elements and shell elements (e.g., where a beam meets a meshed wall). Activate via **Assign → Frame → Automatic Frame Subdivide**. This is particularly important for accurate load transfer between frames and shells. |
| 3.10 | Has the output station spacing been set adequately (e.g., use 2 output station spacing for columns and 3 output station spacing for beams)? |  | Output station spacing controls where internal forces are reported along a frame element. ETABS defaults to a maximum spacing of 0.5 m for beams and a minimum number of stations for columns. For design, a finer spacing (e.g., 0.5 m for beams) captures the critical moment envelope more accurately. |
| 3.11 | Have the shell elements been adequately meshed? (take into consideration solving time and targeted results precision) |  | Mesh size affects accuracy and solution time. A finer mesh gives more accurate results but increases run time. For walls, a mesh size of 0.5–1.0 m is often sufficient; for slabs, 0.5–1.0 m is typical. Use **Assign → Shell → Area Object Mesh Options** to control meshing. |
| 3.12 | Are the auto mesh and auto line constraints options required? If so, have they been activated? |  | Auto line constraints ensure compatibility between shells and frames without creating a fine mesh everywhere. Line constraints automatically appear at interfaces and enforce displacement compatibility when mesh geometries do not match. They eliminate the need for mesh transitioning between mismatched meshes. Activate via **Assign → Shell → Auto Line Constraints**. |
| 3.13 | Are diaphragm constraints used for the slab elements? If so, have they been correctly defined? |  | A rigid diaphragm constraint ties all joints at a floor level together, simulating the in-plane rigidity of a concrete slab. Define via **Define → Diaphragms** and assign via **Assign → Joint → Diaphragms**. For most concrete buildings, a rigid diaphragm is appropriate. |
| 3.14 | Has the diaphragm type (rigid vs. semi-rigid) been chosen appropriately? |  | Rigid diaphragms assume infinite in-plane stiffness; semi-rigid diaphragms model actual in-plane flexibility. For irregular floors or when diaphragm forces are needed for design, use semi-rigid. Note that switching to semi-rigid shells can significantly increase solve time. |
| 3.15 | Have diaphragm forces been checked for chord and collector design? |  | For semi-rigid diaphragms, use section cuts or the “Diaphragm Forces” table to extract chord and collector forces. Define a semi-rigid diaphragm, apply diaphragm forces, then draw or define a section cut where maximum chord forces are expected. Moments in Z are the in-plane moment in the slab; make sure angle is zero. The value of Z moment divided by slab width equals compression and tension chord forces. For collector forces at slab-shear wall connections, draw a section cut next to the support following the wall direction. |
| 3.16 | Have pier labels been assigned to the walls? If so, have the pier labels been correctly assigned to the walls? |  | Pier labels are used for wall design and reporting. Assign via **Assign → Shell → Pier Label**. Ensure that each wall pier has a unique label and that the label is consistent with the design report. |
| 3.17 | Have the column and beam elements been correctly assigned to adequate groups (hint: define and use different elements groups for input checks and output results selection)? |  | Groups allow you to organise elements for selection, design, and reporting. Use **Define → Group Definitions** and **Assign → Assign to Groups**. For example, create separate groups for “Columns – Level 1”, “Beams – Typical Floor”, etc. Groups are essential for efficient model checking and design review. |
| 3.18 | Have the slab and wall elements been correctly set to adequate groups? |  | As with frame elements, use groups to organise shells for design and reporting. For example, create groups for “Shear Walls – Core”, “Shear Walls – Perimeter”, “Slabs – Typical Floor”, etc. |
| 3.19 | Have duplicate, overlapping, or zero-length/short elements been identified and removed? |  | Duplicate or coincident elements (e.g., two beams drawn on top of each other) double-count stiffness and mass, while zero-length or very short members cause ill-conditioning and local instabilities. Use **Analyze → Check Model**, review the analysis log for "zero length" or "duplicate" warnings, and visually inspect with **View → Set Display Options**. Confirm the auto-merge tolerance (see 3.6) is appropriate and that no unintended overlaps exist at grids. |
| 3.20 | Have spandrel labels been assigned to coupling/link beams in shear walls? |  | Spandrel labels identify wall coupling beams for design and reporting (the counterpart of pier labels). Assign via **Assign → Shell → Spandrel Label**. Ensure each spandrel has a unique label and that labels are consistent with the design report. |

## Phase 4 — Pre-Processing: Loads & Boundary Conditions

*This phase defines the external actions and supports on the structure.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 4.1 | Have the static load cases been correctly defined? Has the self-weight multiplier been correctly set? |  | Check **Define → Load Patterns** and **Define → Load Cases**. The self-weight multiplier is typically 1.0 for dead load, but may be adjusted (e.g., 0.9) to account for finishes or to match hand calculations. Ensure all load cases (DL, LL, SDL, etc.) are defined. |
| 4.2 | Have the static loads been correctly assigned on nodes, frames and shells for each static case? |  | Use the **Load Assignments** tables to review loads applied to frames, shells, and joints. Check for any missing or double-counted loads. Spot-check a few elements against the loading plans. |
| 4.3 | Have the load combinations been correctly defined? Have the load factors been correctly chosen? |  | Verify the load combinations in **Define → Load Combinations**. Ensure the factors match the design code (e.g., IS 456:2000, IS 1893:2016). For example, a typical ULS combination is 1.5(DL + LL). Check that all relevant combinations are included. |
| 4.4 | Have the response spectrum functions definitions been correctly calculated (hints: check the seismic site characteristics in terms of peak ground acceleration, corner period, amplification factors, the structure ductility behaviour factor, and check the corresponding defined design spectrum values)? |  | Verify the response spectrum function against the design basis report and the relevant code (e.g., IS 1893:2016). Check the peak ground acceleration (PGA), corner periods, and amplification factors. The design spectrum should be scaled appropriately. |
| 4.5 | Have different behaviour factors on the two horizontal directions been considered? |  | For buildings with different structural systems in the two orthogonal directions, different behaviour factors (R) may be appropriate. Check that the correct R values are used for each direction in the response spectrum load cases. |
| 4.6 | Have the response spectra modal combination and directional combination been correctly ticked (hint: use CQC modal combination method and SRSS directional combination method)? |  | For modal combination, **CQC** (Complete Quadratic Combination) is preferred over SRSS for closely spaced modes. For directional combination, **SRSS** (Square Root of Sum of Squares) is commonly used. Verify these settings in the response spectrum load case definition. |
| 4.7 | Has the additional torsion effect been taken into consideration in the response spectra definition (IS 1893 (Part 1): 2016 requires a ±5% accidental eccentricity of the plan dimension perpendicular to the direction of force)? |  | In ETABS, additional eccentricity can be applied via **Define → Mass Source** or by using the **Accidental Eccentricity** option in the response spectrum load case. For IS 1893:2016, a ±5% accidental eccentricity is required. The dynamic eccentricity is automatically calculated by the program, while the amount of accidental eccentricity can be specified through the ECC option; if not specified, a default of 5% of the lateral dimension of the floor in the direction of the earthquake will be considered. |
| 4.8 | Have the bi-directional or tri-directional simultaneous seismic action effects been considered in the response spectra definition, according to IS 1893 (Part 1): 2016? Have the response spectrum functions scale factors been correctly set (accordingly to the design response spectrum level and to the simultaneous seismic effects scale factors)? |  | IS 1893:2016 requires consideration of simultaneous action in both horizontal directions (e.g., 100% X + 30% Y), combined per the 100:30:30 rule. This can be achieved by defining separate response spectrum load cases and combining them with the appropriate scale factors. Check the scale factors and combination rules. |
| 4.9 | Has the main seismic direction action been considered on both principal horizontal directions of the building (e.g., 100%x+30%y and 30%x+100%y for the bi-directional simultaneous seismic action)? |  | Ensure that the load combinations include both principal directions with the correct participation factors. For IS 1893:2016, combine the horizontal components as ±1.0 E<sub>x</sub> ± 0.3 E<sub>y</sub> and ±0.3 E<sub>x</sub> ± 1.0 E<sub>y</sub> (and include ±0.3 E<sub>z</sub> when the vertical component is considered, per the 100:30:30 rule). |
| 4.10 | Has the base nodes of the model been restrained (hint: use graphical option “supports”)? |  | Use the **Assign → Joint → Restraints** command to verify base supports. Check for any unintended releases or springs. The support conditions should match the foundation design assumptions (e.g., fixed, pinned, or spring supports). |
| 4.11 | Have the storey-level eccentricity between the centre of mass and centre of rigidity been checked? Does this eccentricity reflect the general configuration of the building? |  | ETABS reports the centre of mass and centre of rigidity for each floor. Compare the eccentricity with the building geometry. Large eccentricities may indicate an irregular layout that requires additional torsion considerations. |
| 4.12 | Have the wind loads been defined correctly (wind load pattern, exposure, pressure coefficients, and wind load cases)? |  | For wind-governed buildings (or where required by code), define wind loads per IS 875 (Part 3): 2015. In ETABS use **Define → Load Patterns** (type = wind) and assign exposure, wind pressure coefficients, and gust factors, or use the auto lateral wind load with the correct windward/leeward pressure coefficients. Verify the basic wind speed, terrain category, importance/topography factors, and the design wind pressure against the design basis report. For tall or wind-sensitive buildings, also check wind drift and along/across-wind acceleration limits (see IS 16700:2017). |
| 4.13 | Have snow, roof live, and temperature load patterns been defined where applicable? |  | Beyond DL/LL/SDL, define any applicable loads: imposed/roof live per IS 875 (Part 2): 1987, snow per IS 875 (Part 4): 1987, and temperature/special loads per IS 875 (Part 5): 1987. Confirm the load patterns and cases are consistent with the design basis and that temperature gradients (ΔT) match the specified range. |
| 4.14 | Have notional (or minimum) lateral loads been applied for stability checks? |  | For stability-sensitive frames, apply notional horizontal loads to account for imperfections and out-of-plumb (per IS 800:2007, effects of imperfections; equivalent logic applies to slender RC frames). Also confirm the design base shear is not less than the minimum required by IS 1893 (Part 1): 2016. Notional loads should be combined with the gravity load cases and reviewed for sway sensitivity. |
| 4.15 | Have foundation/soil flexibility and supports (springs) been modelled correctly where applicable? |  | If footings, rafts, or piles are modelled, verify the spring stiffnesses (vertical, lateral, rocking) are based on the geotechnical report and that uplift/lift-off is handled appropriately. For fixed-base assumptions, confirm the restraints in 4.10 match the foundation design. IS 1893 (Part 1): 2016 allows soil-structure interaction to be considered where relevant. |

## Phase 5 — Analysis Configuration

*This phase covers the solver settings and analysis options.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 5.1 | Have the correct analysis cases been selected to run (static, modal, response spectrum, P-Delta, nonlinear)? |  | In ETABS, go to **Analyze → Set Load Cases to Run** and verify that all required analysis cases are selected. Ensure that modal cases, response spectrum cases, and any nonlinear cases are included. |
| 5.2 | Has the modal analyses options been set (use Ritz analysis type and correct Ritz load vectors setting)? |  | For seismic analysis, the **Ritz** method is generally preferred over Eigenvector because it captures the dynamic behaviour more efficiently, especially for buildings with many modes. Ensure that the Ritz load vectors include the appropriate acceleration directions. Set the modal damping ratio to 5% for reinforced concrete (the value for which the IS 1893 (Part 1): 2016 design spectrum is defined). |
| 5.3 | Has the P-Delta effect been considered where required? |  | P-Delta analysis should be activated when the stability coefficient (θ) exceeds 0.10. Check the P-Delta parameters in ETABS (**Define → P-Delta Options**). The P-Delta load combination should include the appropriate gravity loads. |
| 5.4 | Has the stability coefficient (θ) been calculated and checked? |  | θ = (P × Δ) / (V × h). If θ > 0.10, second-order effects must be considered. If θ > 0.25, a rigorous second-order analysis is required, and if θ > θ<sub>max</sub>, the structure is potentially unstable and shall be redesigned. The stability coefficient is calculated as θ = (P<sub>x</sub> × Δ × I<sub>e</sub>) / (V<sub>x</sub> × h<sub>sx</sub> × C<sub>d</sub>), where P<sub>x</sub> is total vertical design load at and above level X, Δ is design story drift, V<sub>x</sub> is seismic shear force, h<sub>sx</sub> is story height, I<sub>e</sub> is importance factor, and C<sub>d</sub> is deflection amplification factor. |
| 5.5 | If performing nonlinear analysis, have hinge properties and convergence criteria been correctly defined? |  | Check that hinge properties (e.g., ASCE 41-23) are assigned correctly and that the hinge definitions match the expected failure modes. Review the analysis log for convergence issues. Non-convergence may indicate instability, incorrect hinge properties, or load application errors. |
| 5.6 | Have the solver options and convergence settings been set appropriately? |  | Check the solver type, convergence tolerances, and iteration limits (**Analyze → Analysis Options**). For linear analyses the default solver is usually adequate; for ill-conditioned or nonlinear models, tighten tolerances and increase iteration limits. Review the analysis log for solver messages, negative eigenvalues, and convergence warnings (see Phase 6). |

## Phase 6 — Analysis Execution & Diagnostics

*This phase covers running the analysis and reviewing the output for errors or warnings.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 6.1 | Has the *.log file been checked for warnings and error messages? |  | After running the analysis, open the **Analysis Log** file (usually with a .log extension) and review any warnings or errors. Common issues include instability, unconnected joints, and zero-stiffness elements. Address all warnings before proceeding. |
| 6.2 | Has the global force balance been reviewed for each analysis case? |  | ETABS computes global force balance for Loads, Modes, Specs, and Combos to ensure that forces and moments within each Analysis Case are in equilibrium. Results are reported in .OUT and .LOG files, which should be reviewed to validate the model and analysis. For each Analysis Case, resultants are computed at the global origin for forces and moments of applied loads, inertial loads, spring forces, link forces, restraint forces (reactions), constraint forces, and P-Delta forces. Zero total resultant indicates equilibrium for each DOF at the origin, though a solution of exactly zero cannot occur due to round-off. Global force balance relative errors should be very small—in the order of 10e-10 and less. |
| 6.3 | Have negative stiffness or negative eigenvalues been identified? |  | All three solvers report the number of negative stiffness eigenvalues found during linear equation solving (“number of eigenvalues below the shift”). If the number of negative stiffness eigenvalues is not zero, a serious problem exists. This could be due to instability, very poor conditioning, or to buckling under P-Delta. For stability, the number of negative stiffness should be zero and the negative eigenvalues should also be zero. |
| 6.4 | Has a free-free mode check been performed to verify connectivity? |  | Run an unconstrained modal analysis to verify connectivity. Rigid-body modes should appear as zero-frequency modes. If the number of zero-frequency modes is less than six, the model has connectivity issues (unconnected joints or elements not properly attached). |
| 6.5 | Do the sum of reactions equal the sum of applied loads? Do moment equilibrium checks pass? |  | Sum of reactions should equal sum of applied loads. For force equilibrium: ΣF = 0; for moment equilibrium: ΣM = 0. A general passing criterion for relative error is below 0.1%. ETABS reports restraint forces (reactions) as part of the global force balance check. |

## Phase 7 — Post-Processing & Results Validation

*This phase verifies that the results make physical sense before they are used for design.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 7.1 | Does the deflected shape under gravity loads have a correct look? Do excessive deflections exist? |  | Display the deformed shape under a gravity load case (e.g., DL + LL). Check for any unexpected deformations, such as excessive sagging or localised anomalies. Compare the maximum deflection with hand calculations or code limits. View the deformed shape to reveal modelling errors such as excessive deflections or nodes “flying off the page.” |
| 7.2 | Has the total hand-calculated weight of the building been compared with the sum of the vertical reactions (ETABS output) for a given static load combination? |  | Sum the vertical reactions from the ETABS output table and compare with a hand-calculated estimate of the building weight. The two values should be within a few percent. This is a powerful check for gross modelling errors. |
| 7.3 | Has a vertical column base reaction (ETABS output) been compared with a hand-calculated result for a given vertical static combination? |  | Select a typical column and compare its base reaction from ETABS with a hand calculation based on tributary area. Discrepancies may indicate load assignment errors or incorrect modelling of load paths. |
| 7.4 | Has the total mass of the building (ETABS output) been compared with a hand-calculated evaluation? |  | ETABS reports the total mass in the **Mass Summary** table. Compare this with a hand-calculated mass based on member sizes, densities, and superimposed loads. Note that the self-weight multiplier (e.g., 0.9) should be accounted for. The seismic weight/mass calculated using ETABS should be verified using an analytical method (manual mass calculation). |
| 7.5 | Has the storey-level mass (ETABS output) been compared with a hand-calculated evaluation? |  | Check the mass at a typical floor level and compare with a hand calculation. This helps identify any missing or double-counted loads. Check that story masses are reasonable and consistent across similar floor levels. |
| 7.6 | Have the fundamental periods of the building (ETABS output) been compared with a quick hand-calculated evaluation? (According to Cl. 7.6.2 of IS 1893 (Part 1): 2016 or to other technical references) |  | Use empirical formulas (e.g., T = 0.075 H<sup>0.75</sup> for RC frames) to estimate the fundamental period. Compare with the modal analysis results. Large discrepancies may indicate modelling issues (e.g., incorrect stiffness or mass). |
| 7.7 | Have the modal participations mass ratios been analysed? Do they reach the minimum desired 90% value (according to IS 1893 (Part 1): 2016, Cl. 7.7.5.2) on each direction? |  | Check the **Modal Participating Mass Ratios** table. For each principal direction, the cumulative mass participation should exceed 90%. If not, increase the number of modes considered. Most seismic codes require at least 90% cumulative modal mass participation. |
| 7.8 | Is the structure sensitive to torsion? (For not being sensitive to torsion it is recommended the fundamental torsion mode to be uncoupled to the fundamental translational modes and the torsion fundamental period to be lower than the translational fundamental periods) |  | Review the mode shapes and periods. If the first mode is torsional or if torsional and translational modes are closely coupled, the structure may be torsionally sensitive. Check the **Modal Direction Factors** in the ETABS output. Compare maximum and average story drifts at each level: a ratio D<sub>max</sub>/D<sub>av</sub> > 1.2 indicates torsional irregularity; > 1.4 indicates extreme irregularity. |
| 7.9 | Can the building configuration be improved to reduce the torsion effect? |  | If torsion is significant, consider adjusting the structural layout (e.g., redistributing shear walls) to align the centre of mass and centre of rigidity. This is a design decision that may require iteration. |
| 7.10 | Has the base shear force been compared with a quick hand-calculated evaluation? (established on Equivalent Lateral Force methodology in IS 1893 (Part 1): 2016) |  | Calculate the base shear using the equivalent static method (V<sub>b</sub> = A<sub>h</sub> × W) and compare with the ETABS response spectrum base shear. Many codes require that the dynamic base shear be scaled to at least a certain percentage of the static base shear (e.g., 100% for IS 1893:2016; 85% for ASCE 7-22). If the response spectrum base shear is less than the required percentage of the static base shear, the scale factor should be adjusted accordingly. |
| 7.11 | Does the storey shears vertical distribution have a correct shape? |  | Plot the storey shears from ETABS and check that they generally increase towards the base. Sudden jumps or drops may indicate a modelling error or an unexpected stiffness irregularity. |
| 7.12 | Does the storey-level shear force distribution (in columns and walls) confirm the assumed structural behaviour? |  | Review the shear force distribution in vertical elements. Check that the shear is distributed in a manner consistent with the structural system (e.g., shear walls taking the majority of the lateral load in a wall-frame system). |
| 7.13 | Do the maximum story drifts from seismic action satisfy the code limitations (check Cl. 7.11.1 of IS 1893 (Part 1): 2016)? |  | IS 1893:2016 limits storey drift to 0.004 times the storey height under design basis earthquake forces. Check the **Story Drifts** table in ETABS and compare with the limit. Note that ETABS does not automatically apply the C<sub>d</sub> amplification factor; this must be done manually for certain codes. |
| 7.14 | Have the maximum horizontal displacement been checked (hint: read horizontal displacements from seismic action at roof level and compare them with quick hand-calculated estimates)? |  | Use the **Joint Displacements** table to obtain the roof displacement. Compare with a hand estimate (e.g., using the equivalent static method). Large discrepancies may indicate a modelling issue. |
| 7.15 | Do ‘in elevation’ deflected shapes indicate correct frame behaviour, if the case? (engineering unexpected deformed shapes might reveal geometric errors or wrong loads directions) |  | Display the deformed shape for the seismic load case. Check that the deflected shape is smooth and consistent with the structural system. Anomalies may indicate disconnected elements or incorrect boundary conditions. |
| 7.16 | Do the elements vertical deflections satisfy codes limitations? |  | Check the vertical deflection of beams and slabs under service loads. Compare with code limits (e.g., IS 456:2000 (span/250) for total deflection). This check may require reinforcement details for accurate assessment. |
| 7.17 | Do the first three mode shapes show expected behaviour (translation X, translation Y, torsion)? |  | Display the first few mode shapes. If the torsional mode appears first or has a high participation factor, the structural framing may need revision. Unexpected shapes (e.g., local modes, excessive torsional coupling) may indicate modelling errors such as incorrect releases or stiffness assignments. |
| 7.18 | Do the program-suggested member sizes align with engineering intuition based on span and loading? |  | Review the design output for member sizes. Significant deviations from expectations may indicate the model is not working as intended. |

## Phase 8 — Design & Reporting

*This phase covers the transition from analysis results to design output and documentation.*

| Ref | Question | Answer | Guidance Notes |
|---|---|---|---|
| 8.1 | Has the general overturning moment been compared against simple hand calculations / checks? |  | Compute the overturning moment by summing the product of storey shear and height. M<sub>OT</sub> = Σ(F<sub>i</sub> × h<sub>i</sub>) — cumulative seismic moment from that story to the roof. The resisting moment comes from the building's gravity load acting relative to the overturning edge. Compare with a hand calculation based on the equivalent static method. The values should be of the same order of magnitude. |
| 8.2 | Have all the calculated steel quantity in beams / column / walls / slab satisfied the maximum allowable limit? |  | ETABS reports the reinforcement ratios in the design output. Check that these do not exceed the maximum limits specified by the code (beams: max 4% tension reinforcement per IS 456:2000 Cl. 26.5.1.1; columns: max 6% longitudinal reinforcement away from laps, 4% at lap locations, per IS 456:2000 Cl. 26.5.3.1). |
| 8.3 | Have the columns been checked when subjected to axial compression loadings in the seismic load combinations (The ratio of axial force over design axial capacity)? |  | Review the **Column Design** output and check the axial force versus capacity ratio (DCR). Columns should have adequate capacity under seismic combinations. The DCR is calculated as DCR = Axial<sub>max</sub> / Axial<sub>p</sub>. The P-M-M ratio (also known as the Demand-Capacity Ratio or DCR) is essentially P-M-M Ratio = Demand (P, M, M) / Capacity (P, M, M). All DCR values should be less than 1.0. |
| 8.4 | Have you considered specific design rules to ensure the desired yielding mechanism? (ensure that the hierarchy of yielding is respected) |  | Check for weak-storey mechanisms by reviewing the lateral stiffness distribution. A soft storey is defined as a storey whose lateral stiffness is less than 70% of the storey above, or less than 80% of the average stiffness of the three storeys above. In ETABS, the check is not automatic. Go to **Display → Show Tables → Results → Story Stiffness**, then manually compare adjacent stories against the 70/80% thresholds (per IS 1893 (Part 1): 2016, Table 6(i)). For capacity design and ductile detailing (strong-column weak-beam), refer to IS 13920:2016. |
| 8.5 | Have soft storey or weak storey irregularities been identified? |  | A weak storey is a storey whose lateral strength is less than that of the storey above. A soft storey is a storey whose lateral stiffness is less than 70% of the storey above or less than 80% of the average stiffness of the three storeys above (per IS 1893 (Part 1): 2016, Table 6(i)). Use the **Story Stiffness** table to identify any soft storeys. |
| 8.6 | Have the design sections been verified against the analysis sections? |  | ETABS allows multiple design iterations without re-running analysis. Use **Design → Verify Analysis vs Design Section** to check that the sections used in design match those used in analysis. |
| 8.7 | Have the model assumptions been documented? |  | Record all key assumptions: material properties, stiffness modifiers, diaphragm behaviour, load combinations, and any simplifications. This is essential for review and future reference. |
| 8.8 | Has an independent check been performed on critical results? |  | Have another engineer independently verify key results (e.g., base shear, fundamental period, maximum drift, column reactions) using hand calculations or a different software. Complex models should be accompanied by easy benchmark models to build understanding and trust in the results. |
| 8.9 | Have the design preferences (clear cover, bar size selection, design combinations) been set correctly? |  | In **Design → Concrete Frame Design → Design Preferences**, set the clear cover to beams, columns, walls, and slabs per IS 456:2000 (Cl. 26.4 and Table 16), specify the longitudinal and shear bar size selection rules, and select the design load combinations used for design. For seismic detailing (confinement, lap zones, capacity design), refer to IS 13920:2016. |

## Summary of Phases

| Phase | Focus | Key Check Areas |
|---|---|---|
| **1. Model Planning & Setup** | Define the problem and assumptions | Analysis objective, model type, units, design code, stiffness assumptions, mass source |
| **2. Pre-Processing: Geometry & Materials** | Define the physical structure | Grid/storey data, materials (incl. densities), element positioning, sections, local axes |
| **3. Pre-Processing: Elements & Connectivity** | Define structural topology | Connectivity, releases/offsets, meshing, diaphragms, duplicate/zero-length elements, groups/labels, pier/spandrel labels |
| **4. Pre-Processing: Loads & Boundary Conditions** | Define actions and supports | Load patterns/assignments, combinations, wind & seismic response spectra, snow/temperature, notional loads, boundary conditions/springs, eccentricity |
| **5. Analysis Configuration** | Configure solver settings | Analysis cases, modal options, P-Delta, stability coefficient, nonlinear settings |
| **6. Analysis Execution & Diagnostics** | Run and check the analysis | Analysis log, global force balance, negative stiffness/eigenvalues, free-free modes, reaction balance |
| **7. Post-Processing & Results Validation** | Verify physical correctness | Deflected shapes, modal results, base forces, displacements/drifts, reaction distribution, member sizes, torsion |
| **8. Design & Reporting** | Transition to design and document | Design preferences (cover/rebar), design section verification, code checks, DCR checks, soft/weak storey checks, documentation, independent verification |
